# Docs

- Design docs live in `docs/` as `design-<topic>.md` and are the source of truth for
  intended behavior. **Write the design doc before coding a feature.**
- When code changes behavior, update the matching design doc in the same change.
- Docs are not code: create/edit them when the user asks, or as part of the
  design-before-code workflow when a feature ships.
- No secrets in docs.
